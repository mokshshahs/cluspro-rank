How to use Paste Manual CSV

Compare docking jobs without the split screen

ClusPro runs every candidate complex as its own job, on its own results page, with no way to see them side by side — so people copy scores into a spreadsheet by hand. This does that part for you: collect each job's cluster table once, then sort, filter, and export one comparison table.

Ranked by cluster size, not by score. ClusPro ranks models by how many docked structures fall into a cluster — the native site tends to sit in the widest energy funnel — and its documentation strongly discourages judging models by the weighted scores, which exist to filter ~109 sampled positions down to 1,000 rather than to rank those final 1,000. The scores are not binding affinities and are not meant for comparison between different jobs. This tool therefore sorts on Members by default and keeps the scores as secondary context. 1. Find the cluster table on ClusPro

On a job's results page, each coefficient set — Balanced, Electrostatic-favored, Hydrophobic-favored, VdW+Elec — has its own tab, and under it a Cluster Scores table. Select that table (from its Cluster  Members  Representative  Weighted Score header row down through the last cluster) and copy it.

2. Pick the matching tab here before you paste

The copied text does not say which coefficient set it came from — that label lives only in ClusPro's page tabs, outside the selection. So this app cannot detect it, and does not try. The tab you have open on the Paste page is the only thing that decides where a pasted table is filed. Paste a Balanced table with the Electrostatic-favored tab open and it will be filed as Electrostatic-favored.

3. What a valid paste looks like

Cluster    Members    Representative    Weighted Score
0    123    Center    -716.1
Lowest Energy    -770.2
1    114    Center    -754.7
Lowest Energy    -872.7
2    107    Center    -620.8
Lowest Energy    -716.9

The header row is optional; numbered cluster lines are not. Each Lowest Energy line carries no cluster number of its own and is attached to the cluster named above it. Every cluster is stored, not just the first. Anything that doesn't match this shape is rejected with an error rather than half-imported — paste one coefficient set at a time.

4. PDB ID, tags, and building a job across tabs

Each paste needs a PDB ID; the complex/model label and tag are optional. The tag is free text — mutation, construct, batch, run number, whatever you group by. Pasting a second coefficient set for a PDB ID already in the table merges into that job's row instead of creating a duplicate, so you can work through one tab for every job, then switch tabs and do the next set. A job needs data in only one set to be valid; the table shows columns for whichever sets have data.

5. If you paste on the wrong tab

Pasting a set a job already has replaces it, and the app has no way to know that wasn't what you meant. Replacements are flagged in amber rather than green, and an ↩ Undo button appears above the table naming exactly what it will reverse (“Undo: Replaced Balanced for 1LYZ”). Ctrl/⌘ + Z does the same, except while you're typing in a field. It is one step only — the next change replaces what's undoable. At high volume, still export to CSV every 10–20 jobs as a checkpoint.

6. Choosing the headline score

Above the results table, Headline score picks which number from a job's stored cluster table appears in the row: cluster 0's Lowest Energy (the default), cluster 0's Center, a specific cluster number, or the global minimum across every cluster. Changing it recomputes every row instantly — nothing is re-pasted. To override one row, expand it with ▸ and click any value to pin it. Rules match ClusPro's cluster number, so a table copied from partway down has no cluster 0 and shows “—” rather than passing off another cluster's score.

7. Getting the table out

Export table writes exactly what's on screen — current coefficient set, sort, filter, and top-N — for dropping into a paper or poster. Export all sets writes every row and set, ignoring the filter, as a reload-able backup. There is no autosave: a refresh clears everything, so export before you close the tab.

Header names are matched loosely, a bare balanced column is read as its center score, and unrecognised columns are ignored and reported. A long format with a coefficient_set column also works.
